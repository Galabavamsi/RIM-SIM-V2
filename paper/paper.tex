\begin{abstract}
Reconfigurable Intelligent Surfaces (RIS) enable Smart Radio Environments (SREs) by dynamically controlling the wireless propagation channel. While multiple testbeds now support real-time RIS configuration, practical performance analysis at scale remains challenging due to hardware cost and complexity. We present RIS-SIM v2, a production-grade open-source emulator that replicates RIS-assisted wireless environments at the baseband level with SDR-compatible APIs. The emulator features a comprehensive signal processing pipeline including free-space path loss, per-element RIS channel modeling with vectorized computation, AWGN with configurable noise figure, Rayleigh and Rician fading, and a full suite of RF impairments (CFO, phase noise, IQ imbalance, SFO, and PA nonlinearity). A FastAPI-based web dashboard with Chart.js visualization enables browser-based scenario configuration, real-time constellation monitoring, and post-simulation channel analysis. A ZeroMQ server mode supports machine-to-machine IPC, and parallel Monte Carlo execution via \texttt{ProcessPoolExecutor} enables statistical studies across hundreds of trials. We validate the emulator against laboratory measurements using a fabricated 5$\times$8 RIS prototype at 3.5\,GHz, demonstrating accurate reproduction of spatial power distributions. The emulator's utility is demonstrated in planning a RIS-assisted FM broadcast system for rural coverage at 100\,MHz. RIS-SIM v2 passes 103 unit and integration tests with zero linting errors and is available as open-source software.
\end{abstract}

\section{Introduction}

Sixth-generation (6G) wireless networks must support massive device connectivity, sub-millisecond latency, and AI-native operations under the IMT-2030 framework~\cite{ITU_IMT2030}. Achieving these goals requires a paradigm shift from optimizing only transmitters and receivers to actively manipulating the wireless propagation channel itself---transforming it from a passive entity into an intelligent part of the network, creating a Smart Radio Environment (SRE)~\cite{Smart_Radio_Environments_Di_Renzo}.

Reconfigurable Intelligent Surfaces (RIS) are a key enabling technology for SREs~\cite{Appl_RIS_Wu}. An RIS consists of a planar array of low-cost, passive elements, each applying a controllable phase shift to incident electromagnetic waves~\cite{WC_RIS_basar}. By coordinating these phase shifts, an RIS can beamform reflected signals toward intended receivers, extend coverage, and enhance signal quality---all without active amplification.

While physical testbeds provide the highest realism~\cite{etsiRIS001,tsdsi2023,RISTA,6gbricks_d3_2_2024}, they require expensive hardware (USRPs, RIS panels, anechoic chambers) and are impractical for large-scale studies. Simulation tools have been central to wireless system design for decades~\cite{Survey_on_5G_simulations,survey_network_simulators}, and the concept of the Network Digital Twin~\cite{survey_simulator_emulator_testbed} positions simulation as an integral part of the network lifecycle.

Several RIS simulation tools exist, summarized in Table~\ref{tab:simtools}, but none combine real-time RIS control, SDR-compatible interfaces, web-based configuration, parallel execution, and comprehensive RF impairment modeling in a single open-source package. Our earlier work~\cite{WCL2025,NCC2025} developed a RIS-assisted simulation framework for indoor mobility scenarios. The present paper describes RIS-SIM v2, a complete rewrite that elevates the prototype to production-grade quality.

This paper makes the following contributions:
\begin{enumerate}
    \item A production-grade, modular emulator architecture with in-memory state management, vectorized RIS channel computation, and per-tick instrumentation;
    \item A comprehensive signal processing pipeline including LOS/NLOS propagation, AWGN, Rayleigh/Rician fading, OFDM, and five RF impairment models;
    \item A multi-interface design supporting Python API, CLI, ZeroMQ server/client, and a FastAPI web dashboard with real-time visualization;
    \item Parallel Monte Carlo execution for statistical performance analysis;
    \item Validation against laboratory RIS measurements and demonstration in an FM broadcast coverage planning scenario.

\section{System Architecture}
\label{sec:architecture}

\begin{figure}[t]
    \centering
    \includegraphics[width=\linewidth]{figures/architecture.pdf}
    \caption{RIS-SIM v2 architecture. External entities (signal generators, RIS controllers) interact with the emulator core through standardized SDR-like APIs. The core engine orchestrates mobility, channel modeling, RF impairments, and output generation in discrete time steps.}
    \label{fig:architecture}
\end{figure}

Figure~\ref{fig:architecture} illustrates the high-level architecture. The emulator is organized into three layers: (1) \textbf{external interfaces}---CLI, Python API, ZeroMQ server, web dashboard, and parallel execution; (2) \textbf{core engine}---the discrete-time simulation loop with request handling, mobility updates, and signal processing; and (3) \textbf{signal models}---channel propagation, RF impairments, mobility, and output/metrics.

\subsection{Simulation Loop}

The emulator operates in discrete time steps of duration $\tau$. For mobile nodes, $\tau$ is chosen such that the positional change within a step does not exceed 5\% of the signal wavelength. For static nodes, $\tau$ is based on channel coherence time. At each step, the core engine:

\begin{enumerate}
    \item Applies any pending RIS reconfigurations;
    \item Updates node positions via mobility models;
    \item Assigns queued transmit/receive requests to idle nodes;
    \item Collects per-tick transmit IQ chunks;
    \item Processes reception: applies channel, impairments, and noise per active receiver;
    \item Records output samples and tick-level metrics.
\end{enumerate}

\subsection{Signal Processing Pipeline}

The per-receiver signal processing chain processes IQ samples through:

\[
\mathbf{y}_{\text{rx}} = \left(\sum_{k \in \mathcal{T}} \mathcal{I}_{\text{TX}}(\mathbf{x}_k) \cdot h_k \cdot \mathcal{F}_k\right) \cdot \mathcal{I}_{\text{RX}} + \mathbf{n}
\]

where $\mathcal{I}_{\text{TX}}$ applies TX-side impairments (SFO, IQ imbalance, PA nonlinearity), $h_k$ is the complex channel coefficient for transmitter $k$, $\mathcal{F}_k$ is optional fading, $\mathcal{I}_{\text{RX}}$ applies RX-side impairments (CFO, phase noise, IQ imbalance, SFO), and $\mathbf{n} \sim \mathcal{CN}(0, \sigma^2\mathbf{I})$ is thermal AWGN with $\sigma^2 = kT B \cdot \text{NF} / 2$.

\subsection{Channel Model}

The total channel coefficient between a transmitter at $\mathbf{p}_t$ and receiver at $\mathbf{p}_r$ is:

\[
h = h_{\text{LOS}} + \sum_{m=1}^{M} \sum_{n=1}^{N_m} b_{m,n} \cdot v(\mathbf{p}_t, \mathbf{e}_{m,n}, \mathbf{p}_r, \mathbf{\hat{n}}_m) \cdot h_{\text{in}}^{(m,n)} \cdot h_{\text{out}}^{(m,n)}
\]

where $h_{\text{LOS}} = \frac{\lambda}{4\pi d}\exp(-j2\pi d/\lambda)$ is the free-space LOS component, $b_{m,n}$ is the complex reflection coefficient of the $n$-th element of the $m$-th RIS panel, $v(\cdot)$ is the angular visibility term, and $h_{\text{in}}^{(m,n)}, h_{\text{out}}^{(m,n)}$ are the cascaded free-space coefficients for the incident and reflected paths. The RIS computation is fully vectorized using NumPy broadcasting, enabling real-time processing of panels up to $256 \times 256$ elements.

\subsection{RF Impairments}

The emulator models five RF impairments, applied in physically correct order:

\begin{itemize}
    \item \textbf{Carrier Frequency Offset (CFO)}: $\exp(j \cdot 2\pi \cdot \Delta f \cdot t)$ rotating phasor;
    \item \textbf{Phase Noise}: Wiener process with configurable phase noise density;
    \item \textbf{IQ Imbalance}: $I' = I\sqrt{g}$, $Q' = Q/\sqrt{g} + I\sin(\phi)$;
    \item \textbf{Sample Frequency Offset (SFO)}: linear interpolation resampling;
    \item \textbf{Power Amplifier Nonlinearity}: Rapp model $A_{\text{out}} = A_{\text{in}}G / (1 + (A_{\text{in}}G/A_{\text{sat}})^{2p})^{1/(2p)}$.
\end{itemize}

\subsection{Web Dashboard}

\begin{figure}[t]
    \centering
    \includegraphics[width=\linewidth]{figures/dashboard.pdf}
    \caption{RIS-SIM v2 web dashboard. Left: JSON-based configuration panel with independent topology and signal template selection. Top-right: Room topology with interactive node placement. Bottom: RIS configuration heatmap and IQ time series.}
    \label{fig:dashboard}
\end{figure}

The web dashboard (Figure~\ref{fig:dashboard}) provides a browser-based interface with four tabs: Configuration (JSON editors with topology/signal template selection), Room Topology (interactive canvas with node drag-and-drop), Live View (2$\times$2 grid of constellation, IQ time series, power, and RIS heatmap), and Results (channel analysis bar chart, FFT spectrum, room signal heatmap, and metrics). The backend uses FastAPI with WebSocket push at 20\,Hz for real-time updates.

\subsection{Parallel Monte Carlo}

For statistical studies, \texttt{parallel\_run()} distributes independent simulation trials across CPU cores using \texttt{ProcessPoolExecutor}. Each trial receives a unique seed, and results are aggregated into \texttt{MonteCarloResult} objects supporting SNR CDFs, percentile computation, and visualization.

\section{Numerical Analysis}
\label{sec:numerical}

\subsection{CFO Validation}

\begin{figure}[t]
    \centering
    \includegraphics[width=0.48\linewidth]{figures/cfo_validation.pdf}
    \caption{Estimated vs.\ actual CFO values using BPSK receiver integrated with the emulator. The strong linear correlation ($R^2 > 0.99$) confirms accurate CFO reproduction.}
    \label{fig:cfo}
\end{figure}

To validate the emulator's fidelity, we integrated an in-house BPSK communication system that originally interfaced with USRP hardware. By replacing only the USRP API calls with the emulator's \texttt{send\_to\_simulator()} and \texttt{receive\_from\_simulator()} functions, the BPSK system operated without modification. Figure~\ref{fig:cfo} compares actual CFO values injected by the emulator with those estimated by the BPSK receiver's synchronization algorithm. The near-ideal linear correlation confirms that the emulator accurately reproduces CFO behavior.

\subsection{Real-Time Performance Profiling}

\begin{figure}[t]
    \centering
    \includegraphics[width=0.48\linewidth]{figures/emulation_time.pdf}
    \caption{Wall-clock emulation time $T_{\text{sim}}$ vs.\ number of node pairs on a dual Xeon Gold 6338 server. Real-time operation ($T_{\text{sim}} \leq \tau$) is maintained for up to 10 nodes at $\tau = 1$\,s.}
    \label{fig:emulation_time}
\end{figure}

We profiled the emulator on a dual-socket Intel Xeon Gold 6338 (64 cores, 192\,GB RAM). Figure~\ref{fig:emulation_time} shows the wall-clock time required to process one $\tau$-duration frame as the number of simultaneous transmitter-receiver pairs increases. With all passband processing enabled, real-time operation is maintained for 6, 8, and 10 node pairs at $\tau = 0.3$, $0.5$, and $1.0$ seconds respectively. By selectively disabling passband stages, the emulator scales to 12 nodes.

\subsection{Experimental RIS Validation}

\begin{figure}[t]
    \centering
    \includegraphics[width=\linewidth]{figures/ris_heatmap.pdf}
    \caption{Comparison of normalized received power distributions for the RIS configuration $\{\sigma_1^2\sigma_2^2\sigma_1^2\}$ where $\sigma_1 = 49.64^\circ$ and $\sigma_2 = -153.77^\circ$. Left: Emulator output. Right: Laboratory measurements using a fabricated 5$\times$8 RIS at 3.5\,GHz.}
    \label{fig:ris_heatmap}
\end{figure}

We validated the emulator against laboratory measurements using a fabricated passive RIS with $5 \times 8$ elements. The experimental setup used B200 USRPs with the receiver swept across a polar grid spanning $45^\circ$ at 3.5\,GHz. Figure~\ref{fig:ris_heatmap} compares the emulated and measured received power distributions for a configuration alternating $\sigma_1^2$ and $\sigma_2^2$ phase states. Despite differences in absolute power levels (the emulator outputs gain relative to LOS), the spatial patterns show strong agreement---the emulator reproduces the direction of peak gain and the attenuation characteristics at sector boundaries.

\subsection{Monte Carlo SNR Analysis}

\begin{figure}[t]
    \centering
    \includegraphics[width=0.48\linewidth]{figures/snr_cdf.pdf}
    \caption{SNR empirical CDF from 500 Monte Carlo trials with and without RIS. The RIS provides a median SNR improvement of approximately 7\,dB in this scenario.}
    \label{fig:snr_cdf}
\end{figure}

To demonstrate the parallel Monte Carlo capability, Figure~\ref{fig:snr_cdf} shows SNR CDFs from 500 independent trials with Rayleigh fading. The RIS-assisted configuration achieves a median SNR gain of $\sim$7\,dB over LOS-only propagation, with reduced variance due to the additional propagation paths.

\section{Application: FM Broadcast Coverage}
\label{sec:fm}

\begin{figure}[t]
    \centering
    \includegraphics[width=0.48\linewidth]{figures/fm_coverage.pdf}
    \caption{Received signal power vs.\ distance for a 100\,MHz FM broadcast with a 30$\times$30 RIS deployed for rural coverage enhancement. The green region indicates where the RIS extends coverage beyond the -100\,dBm sensitivity threshold.}
    \label{fig:fm_coverage}
\end{figure}

To demonstrate the emulator's utility in real-world planning, we modeled a rural FM broadcast scenario at 100\,MHz. A transmitter at $(0, 200, 100)$\,m serves a village at approximately 52\,km range. A passive 30$\times$30 RIS with $0.25 \times 0.25$\,m unit cells is deployed at an intermediate location. Figure~\ref{fig:fm_coverage} shows that the RIS-assisted total signal maintains power above the $-100$\,dBm sensitivity threshold between 50--58\,km, where LOS alone would fail. This application demonstrates the emulator's ability to model large-scale, realistic deployment scenarios.

\section{Engineering Quality}

RIS-SIM v2 is developed with production-grade engineering practices:
\begin{itemize}
    \item \textbf{103 automated tests} covering engine correctness, channel models, impairments, OFDM, server round-trips, dashboard endpoints, golden-output regression, and parallel execution;
    \item \textbf{Zero linting errors} (ruff) and \textbf{zero type errors} (mypy) across the codebase;
    \item \textbf{Deterministic reproducibility} via \texttt{SeedSequence} with golden-output regression tests;
    \item \textbf{CI/CD pipeline} (GitHub Actions) testing on Ubuntu, Windows, and macOS across Python 3.10--3.12;
    \item \textbf{Structured logging} with key=value formatting, per-tick performance metrics, and progress reporting;
    \item \textbf{Packaging} via \texttt{pyproject.toml} with optional dependency groups (\texttt{dev}, \texttt{web}).
\end{itemize}

\section{Conclusion}

We presented RIS-SIM v2, a production-grade open-source emulator for RIS-assisted smart radio environments. The emulator combines a comprehensive signal processing pipeline, multiple user interfaces (Python API, CLI, ZeroMQ, web dashboard), parallel Monte Carlo execution, and rigorous engineering quality. Validation against laboratory measurements confirms its fidelity, and an FM broadcast planning case study demonstrates real-world applicability. The emulator is available at \url{https://github.com/Galabavamsi/RIM-SIM-V2} and installable via \texttt{pip install git+https://github.com/Galabavamsi/RIM-SIM-V2.git}.
